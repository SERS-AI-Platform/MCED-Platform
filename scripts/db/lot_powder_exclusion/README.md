# Lot_Powder 워크북 제외 대상 표시

임상정보로 제외 대상 검체를 판정해서 측정 계획 워크북(`검체 측정 Lot_Powder_*.xlsx`)의
DAY 시트에 빨간색으로 표시한다. 2026-07 `0728` 파일에서 손으로 하던 Bold 처리를
자동화한 것이고, 표시 색만 빨간색으로 바뀌었다.

DB가 아니라 Excel을 다루지만, 판정 기준이 `scripts/db/sample_exclusion.sql`과 같은
것이라 나란히 두었다. 기준을 바꿀 때는 두 곳을 같이 고쳐야 한다.

## 실행

```bash
cd scripts/db/lot_powder_exclusion
python3 mark_red.py          # 표시 → 새 워크북 저장 (원본은 건드리지 않음)
python3 verify_marks.py      # 저장된 파일을 다시 열어 검증
python3 validate_rule.py     # 규칙이 이전 수작업 결과를 재현하는지 회귀 검사
```

입출력 경로는 `paths.py`에 있고, 각 스크립트의 `--clinical / --lot / --out`으로
덮어쓸 수 있다. 새 임상표(v9 등)나 새 Lot 파일이 나오면 `paths.py`만 고치면 된다.

**Excel에서 대상 파일을 열어 두면 저장이 막힌다** (`PermissionError`). 닫고 실행할 것.

## 파일

| 파일 | 역할 |
|---|---|
| `paths.py` | 입출력 워크북 경로 |
| `exclusion_rule.py` | **제외 기준 판정.** 기준을 그렇게 정한 근거가 파일 상단 주석에 전부 있다 |
| `lot_map.py` | DAY 시트 셀 ↔ `solum_label` 매핑. 그룹 머리글 → 라벨 접두사 |
| `mark_red.py` | 실행 진입점. 기존 표시 해제 → 빨간색 표시 → 근거 시트 2개 추가 → 저장 |
| `verify_marks.py` | 빨간 번호 집합 일치, 텍스트·수식 무변경, KPAN 미표시 확인 |
| `validate_rule.py` | 워크북에 남아 있는 기존 `제외사유_목록` 83개 라벨을 규칙이 재현하는지 |

`mark_red.py`는 원본 시트를 그대로 두고 `제외사유_목록_v8`, `제외사유_요약_v8` 두 시트를
새로 붙인다. 기존 `제외사유_목록` / `제외사유_요약`은 이전 기록이라 지우지 않는다.

## 제외 기준 (2026-09-07 확정)

| 기준 | 정의 |
|---|---|
| 요로감염 | `ua_nitrite = Positive` |
| 타암 이력 | `past_history_1~9`에 현재 암종과 다른 암/종양 |
| 치료 후 채취 | `collection_date` > `surgery_date` 또는 `chemo_start_date`. 단 `pre_treatment_specimen` 태그가 있으면 제외 안 함 |
| 다중암 | `MULTI_CANCER_PATIENTS`의 환자 — 검체 전부 |
| Drop | `group='Drop'` (임상표 초록색 행) |
| 임상표 노란 표시 | 행 전체가 노란 행 |

2026-09-07 실행 기준 Lot 대상 2,465개 중 **226개** 제외
(방광암 99, 전립선암 36, 대조군 33, 췌장암 22, 대장암 21, 난소암 8, 폐암 7, 유방암 0).

## 결정 사항과 그 근거

**노란 하이라이트는 사유가 아니라 사람이 남긴 표시다.** 워크북에 색 범례가 없어
데이터로 역산했다. 암 코호트의 노란 행 144개 중 121개가 타암 이력, 17개가
nitrite+LE 동시 양성, 4개가 둘 다여서 **142개(98.6%)가 다른 기준으로 설명된다.**
그래도 근거로 남겨 둔 이유는 남는 몇 건을 놓치지 않기 위해서다. 반대로 하이라이트는
암 파일에만 칠해져 있어(대조군·폐암·유방암 0건) 노란색만 믿으면 대조군의 타암 이력
28건을 통째로 놓친다. 그래서 규칙 계산과 합집합으로 쓴다.

**요로감염은 nitrite 하나로 가른다.** 암 코호트에서 nitrite 양성 25건 중 22건이 노란
행인 반면, LE 양성 254건 중 노란 행은 53건뿐이다. LE 단독은 사람의 판단 기준이
아니었다. `../aecd_clinical_v7/08_uti_indicators_view.sql`의 근거(LE 단독은 방광암에서
종양 염증과 구분되지 않음)와도 일치한다. Lot 범위에서 nitrite 단독으로 바꿔도 결과는
같고, LE까지 넣으면 209건이 추가된다.

**타암 판정은 단어 경계로 한다.** `'bladder' in 'Gallbladder cancer'`가 참이라, 부분
문자열로 비교하면 방광암 환자의 담낭암 이력이 자기 암으로 잘못 걸러진다
(`BLC_16`, `BLC_88`, `BLC_147`). `SAME_ORGAN` 비교에 `(?<![a-z])`를 붙인 이유다.

**치료 후 채취는 timing 문자열이 아니라 날짜로 본다.** `primary_sample_timing_interpretation`에
`post_*`가 붙은 검체는 101개지만 그중 6건은 채취일 = 수술일 = 항암시작일로 같은 날이고,
반대로 문자열이 `pre_surgery`/`pre_treatment`인데 날짜상 치료 후인 건이 3건 있다.
`pre_treatment_specimen` 태그가 있으면 살리는 것은 사용자 판단이다.
**단 `PAN_49`·`PAN_64`·`PAN_66`은 채취일이 항암 시작 3~9개월 뒤인데 수술일은 채취일보다
뒤다** — 선행항암 중 검체를 '수술 전'이라는 뜻으로 적은 것으로 보인다. 기준을 다시 볼
일이 있으면 이 3건부터 확인할 것.

**KPAN 열은 판정 대상이 아니다.** 재료연에서 받은 검체라 임상표에 대응 라벨이 없다.
번호만으로는 `PAN`(1~120)과 `SPAN`(1~126) 어느 쪽과도 구분되지 않으므로
(`CPAN`과 53개 번호가 겹친다) 임의로 되살리지 말 것.

**날짜 셀은 문자열과 datetime이 섞여 있다.** `parse_date()`로 양쪽을 다 받아야 한다.
datetime만 보면 문자열 1,414건을 통째로 건너뛰어 "치료 후 채취 3건"이라는 잘못된
결과가 나온다 (실제 173건).

**부분 노란 행은 제외 사유가 아니다.** 셀 1~2개만 노란 행(`BNOR_30`/`BNOR_79`의
weight·height, `BPRO_81`/`BNOR_84`의 treatment_info, `PRO_247`의 diagnosis_date)은
몸무게가 없어서 표시해 둔 것이라 정상 처리한다 (`FULL_ROW_MIN_CELLS = 10`).

## 주의: 워크북에 원래 있던 표시 두 종류

원본 `0907` 파일에는 셀 단위 서식으로 빨간 셀 29개, **그리고 셀 안 번호만 빨간
rich text 셀이 35개** 들어 있었다. rich text 쪽은 `cell.font`로 보이지 않아서
`clear_existing()`이 두 가지를 모두 지운다. 한쪽만 지우면 이전 표시가 남아 과다
표시가 된다.

## 주의: 기존 `제외사유_목록` 시트의 `Lot_Cell` 열은 어긋나 있다

목록은 `DAY 1!K3 = 'CPAN 1'`이라고 하지만 `0907` 파일의 `K3`은 `27,28,29,30`이다.
중간 버전을 기준으로 만들어진 것이라 **셀 주소는 믿으면 안 되고 `solum_label` 열만
유효하다.** `validate_rule.py`가 라벨만 쓰는 이유이고, `제외사유_목록_v8`의 셀 주소는
`0907` 기준으로 새로 계산한 것이다. 기존 목록의 `YPAN_13`은 v7·v8 어디에도 없는
라벨이다.
