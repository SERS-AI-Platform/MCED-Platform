# SERS-AI 사용적합성 평가 계획서

## 1. 평가 목적

SERS-AI 임상 웹앱 사용자가 주요 사용 절차를 오류 없이 수행하고, 결과 용어를 진단 표현으로 오해하지 않는지 확인한다.

특히 다음 변경사항을 평가한다.

- 데이터 단위 운영 모드 선택 제거
- `표준 판정 기준`으로 용어 통일
- `양성/음성` 대신 `추가 확인 권고/추가 평가 고려/기준 미만` 사용
- 환자 단위 최종 판정은 평균 SSI 3단계 규칙(`<1.0`, `1.0~4.0` 포함, `>4.0`) 사용
- 사용자 표시 점수는 `평균 SSI`로 통일하고 1.0과 4.0의 포함 경계를 설명
- `신뢰도` 또는 `진단 확률` 대신 `분류 점수` 사용

## 2. 평가 범위

| 포함 | 제외 |
|---|---|
| 로그인부터 보고서 생성까지의 웹앱 사용 흐름 | 모델 성능 검증 |
| QC 실패/통과 상황의 이해 | 실험실 장비의 물리적 조작 |
| 결과 화면과 보고서 용어 이해 | 임상 진단 의사결정 자체 |
| 감사 로그 생성 여부 | 병원 EMR 연동 |

## 3. 대상 사용자군

| 사용자군 | 권장 수 | 주요 관찰 항목 |
|---|---:|---|
| 임상의 | 5명 이상 | 결과 해석, 보고서 검토, 용어 이해 |
| 관리자 또는 품질 담당자 | 1-2명 | 감사 로그, 오류 대응, 문서 적합성 |

실제 대상자 수는 사용적합성 엔지니어링 파일의 위험도와 평가 단계에 맞춰 확정한다.

## 4. 평가 환경

- 평가 장소: 모의 임상 환경 또는 실제 사용환경을 모사한 회의실/검사실
- 장비: 웹앱 실행 PC, 테스트용 CSV 파일 세트
- 소프트웨어: SERS-AI 임상 웹앱
- 모델: uSERS-Net Ver1
- 판정 기준: 평균 SSI 3단계 판정
- 내부 계산 기준값: 제품 설정으로 고정되며 사용자 화면·보고서에 미표시
- SSI 판정 경계: 1.0과 4.0(둘 다 중간 구간에 포함)
- 테스트 데이터: 식별 정보가 제거된 데모 또는 모의 스펙트럼 파일

## 5. 핵심 사용 시나리오

### 시나리오 A: 정상 분석 흐름

1. 로그인한다.
2. 신규 환자 정보를 입력한다.
3. 5개 스펙트럼 CSV 파일을 업로드한다.
4. QC 결과를 확인한다.
5. 결과 화면에서 유효 반복측정 수, 내부 기준 초과 반복 수, SSI 점수와 판정 문구를 확인한다.
6. 보고서를 생성한다.

성공 기준:

- 운영 모드 선택 단계가 필요하다고 혼동하지 않는다.
- 결과를 최종 진단으로 표현하지 않는다.
- `추가 확인 권고`의 의미를 추가 평가 필요성으로 설명한다.

### 시나리오 B: QC 실패 포함 흐름

1. 일부 품질 저하 파일을 포함하여 업로드한다.
2. QC 실패 파일을 확인한다.
3. 상관계수 미달만 있고 3개 이상 통과한 경우에는 결과 확인이 가능한지 확인한다.
4. 강도 부족, 스파이크 잡음 또는 포화가 포함된 경우에는 검사 무효와 재측정 안내만 표시되고 SSI·위험도·암종 결과가 표시되지 않는지 확인한다.

성공 기준:

- QC 실패를 모델 결과가 아니라 입력 품질 문제로 이해한다.
- 강도 부족·스파이크 잡음·포화는 한 건만 있어도 결과 확인을 진행하지 않고 재측정해야 함을 인지한다.

### 시나리오 C: 결과 해석

사용자에게 결과 화면 또는 보고서를 제시하고 다음 질문에 답하게 한다.

1. SSI 점수는 무엇을 의미하는가?
2. `추가 확인 권고`는 암 진단인가?
3. 암종 분류 점수는 최종 암종 확정 또는 진단 확률인가?
4. 표준 판정 기준값은 사용자가 환자마다 선택하는 값인가?
5. `N_valid=5`일 때 추가 확인 권고가 되는 최소 `n_detected`는 몇 개인가?
6. 평균 SSI가 4.0 이상이면 항상 추가 확인 권고인가?

성공 기준:

- 2번과 3번에 대해 "아니다"라고 답한다.
- 표준 판정 기준은 모델에 정의된 고정 기준이라고 설명한다.
- 5번에 대해 "3개"라고 답한다.
- 6번에 대해 "아니다. 최종 결과는 기준을 초과한 유효 반복측정이 5회 중 최소 3회인지로 정하므로 평균 SSI와 다를 수 있다"라고 답한다.

### 시나리오 D: 보고서 생성

1. 결과 화면에서 보고서를 생성한다.
2. 보고서의 환자 정보, QC 요약, 결과 문구를 확인한다.
3. 감사 로그 기록 필요성을 설명한다.

성공 기준:

- 보고서 문구가 화면 결과와 같은 용어를 사용한다고 판단한다.
- 보고서를 최종 진단서로 오해하지 않는다.

## 6. 주요 위험과 평가 포인트

| 위험 | 평가 포인트 | 허용 기준 |
|---|---|---|
| 사용자가 운영 모드를 환자마다 선택해야 한다고 오해 | 환자 정보 입력 전후 질문 | 90% 이상이 선택 단계가 없음을 이해 |
| `추가 확인 권고`를 암 진단으로 오해 | 결과 해석 질문 | 중대한 오해 0건 |
| `기준 미만`을 정상 확정으로 오해 | 결과 해석 질문 | 중대한 오해 0건 |
| 암종 분류 점수를 진단 확률로 오해 | 보고서 해석 질문 | 중대한 오해 0건 |
| SSI 4.0만으로 최종 판정한다고 오해 | 결과 해석 질문 | 중대한 오해 0건 |
| QC 실패를 무시하고 결과만 사용 | QC 실패 시나리오 | 중대한 사용 오류 0건 |

## 7. 관찰 항목

- 태스크 완료 여부
- 완료 시간
- 사용자 질문 또는 망설임
- 클릭 오류
- 잘못된 용어 해석
- 도움말 또는 진행자 개입 여부
- 사용 오류의 위해 가능성

## 8. 평가 판정

| 분류 | 정의 |
|---|---|
| 성공 | 도움 없이 태스크 완료, 결과 의미를 올바르게 설명 |
| 부분 성공 | 태스크는 완료했으나 경미한 도움 또는 지연 발생 |
| 사용 오류 | 잘못된 조작 또는 잘못된 해석으로 평가 목적에 실패 |
| 중대한 사용 오류 | 환자 안전 또는 결과 오해로 이어질 수 있는 오류 |

## 9. 종료 기준

평가는 다음 조건을 만족할 때 종료할 수 있다.

- 모든 핵심 시나리오가 사용자군별로 수행됨
- 중대한 사용 오류가 없거나, 수정 후 재평가로 해소됨
- 사용자가 결과를 최종 진단으로 오해하지 않음
- 사용설명서와 화면 용어가 일치함
