1. 핵심 개념 — "모델"이라는 단어의 4가지 역할

프로젝트가 헷갈렸던 이유는 "models"라는 이름 하나가 4가지 전혀 다른 것을 같이 담고 있었기 때문입니다. 재구성 후에는 역할마다 다른 디렉토리에 삽니다.

① 데이터 data/
원본 + 전처리
재료
② 정의 src/sers/models/
아키텍처 Python 코드
도면
③ 실행자 scripts/
학습/평가 CLI
시공
④ 산출물 artifacts/ + results/
가중치 + 지표
건물 + 보고서
🔑 기억할 점: 아무것도 학습하지 않는 디렉토리가 3개(data, src/sers/models, artifacts)이고, 학습이 실제로 일어나는 곳은 scripts/ 하나뿐입니다.

비유로 이해하기

프로젝트 개념건축 비유요리 비유
data/재료(벽돌, 철근)식재료
src/sers/models/건축 도면레시피 · 메뉴
scripts/training/시공 팀요리사
artifacts/완공된 건물 (배포 대상)냉장고의 완성 요리 (서빙 가능)
results/공사 보고서 · 검수 기록매번의 요리 시식 기록
config/시방서표준 조리법 세부 스펙

2. 7가지 최상위 디렉토리

① 입력

data/

스펙트럼 원본 + 표준화된 임상 CSV.

소비자: preprocessing · training 스크립트

재생성: ❌ (원본). git: ❌ (gitignored)

② 정의(라이브러리)

src/sers/

다른 코드가 import 하는 순수 Python 라이브러리. 부작용 없음.

주요 서브패키지: io/, preprocessing/, qc/, features/, models/, validation/, visualization/, cli/

③ 실행자(CLI)

scripts/

사람이 CLI로 실행하는 얇은 엔트리포인트. src/sers/ 를 import해서 사용.

서브폴더: training/, evaluation/, experiments/, analysis/, pipeline/, figures/, deployment/, db/, qc_validation/

④ 학습된 가중치

artifacts/

production inference가 로드하는 직렬화된 학습 상태. Semver 버저닝.

usersnet/v1.0.0/ + current symlink
baselines/lr-fusion/v1.0.0/, resnet18/, sersnet-ensemble/

④ 실험 결과

results/

사람이 읽는 실험별 수치·예측·진단 그림.

runs/{YYYY-MM-DD}_{model}_v{ver}_{mode}/ · comparisons/ · benchmarks/

④ 출간물

figures/

논문·포스터·슬라이드용 최종 렌더링. 재실행으로 생기는 실험 그림은 여기 오지 않음.

paper/, poster/, slides/

⚙️ 설정

config/

YAML/JSON/TOML 런타임 설정. 코드가 아닌 값.

config.yaml, environment.yml

3. 한 번의 학습 실행 흐름도

"sers train --model usersnet" 을 한 번 실행하면 아래처럼 움직입니다.

[사용자 명령] $ sers train --model usersnet │ ▼ ┌─────────────────────────────────────┐ │ scripts/training/train_usersnet.py │ ← ③ 실행자 │ (읽고 → 학습 → 저장) │ └──────┬─────────┬─────────┬──────────┘ │ │ │ 읽기 ◄─┘ import 쓰기 ──┐ │ │ │ ▼ ▼ ▼ ┌──────────┐ ┌──────────────┐ ┌───────────────────────┐ │ data/ │ │src/sers/ │ │artifacts/usersnet/ │ │ raw, │ │models/ │ │ v1.0.1/ ← 새 weights│ │ clinical │ │ usersnet/ │ │ manifest.json │ │ │ │ stacking.py │ └───────────────────────┘ │ ① 입력 │ │ ② 정의 │ └──────────┘ └──────────────┘ ┌───────────────────────┐ │results/runs/ │ │ 2026-04-15_usersnet_ │ │ v1.0.1_holdout/ │ │ manifest.json │ │ metrics.json │ │ predictions/*.npz │ │ figures/*.png │ │ logs/*.log │ └───────────────────────┘ ④ 산출물
💡 포인트: script 자체는 scripts/ 에 그대로 남고, 실행마다 results/runs/{run-id}/ 가 새로 하나씩 생깁니다. script는 "영구 저장소", results는 "실행 기록소".

4. scripts/ → results/ 대응표

각 실행 스크립트가 어디에 산출물을 만드는지 한눈에:

실행자 (scripts/)출력 목적지설명
scripts/training/train_usersnet.py results/runs/{date}_usersnet_v{ver}_{split}/ + artifacts/usersnet/v{ver}/ uSERS-Net 학습 (production)
scripts/training/build_usersnet_production.py artifacts/usersnet/v{ver}/ 전체 데이터로 최종 production 빌드
scripts/training/_legacy/train_resnet.py results/runs/{date}_resnet18_.../ + artifacts/baselines/resnet18/ ResNet baseline 학습
scripts/training/_legacy/build_lr_fusion.py artifacts/baselines/lr-fusion/v1.0.0/ 구 LR+Clinical 재빌드
scripts/training/_legacy/run_sersnet_ensemble.py artifacts/baselines/sersnet-ensemble/v1.0.0/ 0.8·LR_fusion + 0.2·ResNet 블렌딩
scripts/evaluation/eval_usersnet_holdout.py 기존 run 폴더에 metrics.json, predictions/ 갱신 Train/Val/Test 60/20/20 최종 평가
scripts/analysis/xai_fusion_analysis.py results/analysis/xai_{date}/ FiLM/CrossAttn SHAP 해석
scripts/analysis/confounding_analysis.py results/analysis/confounding_{date}/ 연령·성별 교란 분석
scripts/figures/plot_overall_comparison.py figures/paper/ 또는 results/comparisons/.../figures/ 논문용 모델 비교 figure
scripts/experiments/_archive/2026-03_step5_ensemble.py results/_archive/step5_ensemble/ 완료된 ablation (아카이브)
sers compare --models a,b,c results/comparisons/{date}_{a_vs_b_vs_c}/report.md 🆕 자동 비교 리포트

5. 자주 묻는 질문에 대한 답

Q1. models/는 "우리 데이터를 학습하는 디렉토리"인가?

아닙니다.

  • src/sers/models/ 는 학습될 설계도(청사진)가 담긴 디렉토리 — 학습을 "하는" 게 아니라, 학습에 필요한 아키텍처 정의를 제공.
  • 데이터는 data/ 에만 있음 — models/ 에는 데이터가 없음.
  • 학습을 실행하는 주체는 scripts/training/*.py.

그리고 루트 레벨의 models/ 는 이제 4개 파일만 남은 deprecation 호환 껍데기입니다 (§6 참조).

Q2. results/ 는 각 모델이나 실험마다 하나씩 생기는가?

맞습니다. results/runs/ 밑에 실행마다 {YYYY-MM-DD}_{model}_v{ver}_{mode} 형식의 폴더가 새로 생깁니다.

results/
├── runs/
│   ├── 2026-04-14_usersnet_v1.0.0_holdout/    ← 한 번의 실행
│   ├── 2026-04-15_usersnet_v1.1.0_holdout/    ← 재학습 (clinical fusion)
│   └── 2026-04-16_resnet18_v1.0.0_holdout/    ← baseline 비교
├── comparisons/    ← sers compare 출력
├── benchmarks/     ← 표준 벤치마크 추적
└── _archive/       ← 옛 실험 결과

Run-id는 불변(immutable)입니다. 덮어쓰지 않고 새 폴더가 쌓임 → 실험 감사 추적.

Q3. scripts/ 안의 내용이 results/ 실험별로 이동하는가?

부분적으로 맞음. script 코드는 그대로 scripts/에 남고, script가 생산한 산출물이 results/로 갑니다.

항목사는 곳
script 코드 (train_usersnet.py)scripts/training/ — 영구 보관
script 실행 결과 (metrics, 예측)results/runs/{run-id}/ — 매 실행 새 폴더

비유하면, train_usersnet.py는 레시피(한 번 작성, 영구), results/runs/2026-04-14.../는 그 레시피로 요리한 결과물.

Q4. 새 모델을 추가하려면 어디부터 건드려야 하나?
  1. src/sers/models/_registry.py 에 ModelSpec 엔트리 추가
  2. docs/MODEL_STATUS.md 에 같은 키 + 사유 기재 (parity 테스트가 강제)
  3. 모델 정의 모듈 생성: src/sers/models/{카테고리}/{이름}/
  4. 학습 스크립트 생성: scripts/training/{train_name}.py
  5. pytest tests/test_model_registry.py 실행해서 통과 확인

models/는 왜 아직 남아 있는가?

⚠️ Deprecated: 루트의 models/ 는 호환 전용 껍데기입니다. 이 안에 새 코드·아티팩트·결과를 넣지 마세요.

현재 남은 4개 파일

파일역할동작
models/__init__.py 패키지 진입점 + DeprecationWarning import models 시 "top-level models.* is deprecated; use sers.models.*" 경고 발생
models/train.py from models.train import load_processed_spectra, ... 호환 scripts/training/_legacy/train_resnet.py 를 동적 로드해서 심볼 재노출
models/train_stacking.py from models.train_stacking import ... 호환 scripts/training/train_usersnet.py 를 동적 로드
models/run_train_val_test.py archive 실험 import 호환 scripts/experiments/_archive/2026-04_train_val_test_split.py 동적 로드

왜 즉시 삭제하지 않았나?

두 가지 이유로 단계적 제거를 선택했습니다.

  1. 대량 import 의존성 — from models.train import ... 패턴이 scripts/analysis/, scripts/experiments/_archive/, scripts/qc_validation/, 외부 폴더(AACR/, publications/, metabolite_profiling/)까지 총 30여 개 파일에 퍼져 있었습니다. 한 번에 sed 로 바꾸지 않고 점진적으로 사용처를 줄여나가기 위함.
  2. 현재 train.py (구 ResNet) 의 라이브러리성 함수 — load_processed_spectra, get_feature_columns, aggregate_replicates, resolve_aliases, train_fold, create_labels 등은 원래는 src/sers/ 라이브러리로 추출됐어야 할 코드인데, 현재는 스크립트 내부에 바인딩돼 있습니다. shim은 이 함수들이 계속 import 되도록 우회 경로를 제공합니다.

제거 타임라인

단계조건조치
v0 (지금) 재구성 직후 shim 작동 + DeprecationWarning 발생
v1 from models.* 사용처가 0 으로 줄면 models/ 전체 삭제
v1 선행 조건 - train.py 내부 라이브러리 함수들을 src/sers/models/_legacy/resnet_v1/training_lib.py 로 추출
✅ 새 코드 작성 원칙: from models.X import ... 대신 from sers.models.X import ... 를 사용하세요. Deprecation 경고가 보이면 그 파일이 아직 옛 경로를 쓴다는 신호 — 업데이트 대상.

7. 판정 프레임워크 — 새 파일이 어디로 갈지

애매한 파일이 생기면 7가지 질문에 순서대로 답하세요. 첫 YES 답이 목적지.

Q1. 다른 파이썬 코드가 import 하는가?     ──► src/sers/
Q2. CLI에서 사람이 실행하는 .py 인가?       ──► scripts/
Q3. production inference가 로드하는가?      ──► artifacts/
Q4. 실험별로 비교할 수치/예측/진단인가?     ──► results/
Q5. 논문·포스터·슬라이드에 들어가는 이미지? ──► figures/
Q6. YAML/JSON/TOML 설정값인가?              ──► config/
Q7. 입력 원본·중간 데이터인가?              ──► data/
원칙: 한 파일이 두 질문에 YES 면 그 파일은 쪼개야 한다는 신호입니다. 예: "이 .py는 import도 되고 CLI로도 실행된다" → 라이브러리 부분(src/)과 CLI 래퍼(scripts/)로 분리.

자주 헷갈리는 경계 케이스

상황판정
학습된 *.joblib "production inference가 로드?" → YES 면 artifacts/, NO 면 results/{run}/
혼동행렬 PNG 실험 품질 점검용 → results/runs/{id}/figures/ · 논문 수록 → figures/paper/
build_production_*.py __main__ + argparse 있음 → scripts/training/ (모델 정의 아님)
*_utils.py 다른 파일이 import 함 → src/sers/
Jupyter notebook 탐색 → notebooks/ · 재현 분석 → 코드 scripts/figures/, 결과 results/
