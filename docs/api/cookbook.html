1uSERS-Net 빠르게 "건강 체크"

지금 레지스트리·현 production·환경이 정상인지 1분 안에 확인.

명령 
$ sers --help
$ sers train --help
$ python -c "from sers.models._registry import MODEL_REGISTRY; print(len(MODEL_REGISTRY), 'models')"
$ ls artifacts/usersnet/current/
$ pytest tests/test_model_registry.py -q
예상 출력 
9 models
base_lr_concat_s1.joblib  base_lr_d1_s1.joblib  ... meta_s1.joblib  meta_s2.joblib
======================== 7 passed in 0.9s ========================
💡 이 5개 명령이 전부 정상이면 → 재구성이 안정 상태. 하나라도 실패하면 recipe 8(트러블슈팅)로.

2uSERS-Net 재학습 (v1.0.X 패치)

데이터가 추가됐거나 hyperparameter 를 살짝 바꿨을 때. 아키텍처 변경은 아님.

입력 (data/)
data/ ├── processed/ ← QC/전처리 완료 스펙트럼 └── clinical_data/standardized/ └── all_clinical_standardized.csv
명령 
# (1) 먼저 빠른 sanity check — 1 fold, 3 base models
$ sers train stacking --dry-run

# (2) 진짜 학습 — nested 5x3 CV + SHAP + confusion matrix
$ sers train stacking

# (3) SHAP/CM 은 생략하고 싶으면
$ sers train stacking --no-shap --no-cm
출력
results/runs/2026-04-XX_usersnet_v1.0.X_nested_cv/ ├── manifest.json # 실행 config + git commit ├── metrics.json # AUC, F1 per-fold + overall ├── predictions/ │ └── oof_predictions.npz ├── figures/ │ ├── confusion_matrix.png │ └── shap_summary.png └── logs/ └── training.log
검증 
$ cat results/runs/2026-04-*_usersnet*/metrics.json | python -m json.tool
$ ls results/runs/2026-04-*_usersnet*/figures/
⚠️ 학습은 production artifact 를 자동으로 교체하지 않습니다. 교체하려면 Recipe 5 (production 빌드) 를 이어서 실행.

3Legacy baseline 학습 (ResNet18 / LR-Fusion / SERS-Net Ensemble)

uSERS-Net 성능을 비교할 baseline 수치 확보.

명령 
# (a) ResNet18-1D 5-fold CV
$ sers train resnet18
$ sers train resnet18 --epochs 200 --lr 3e-4

# (b) 구 LR-Fusion production 재빌드
$ python scripts/training/_legacy/build_lr_fusion.py

# (c) SERS-Net Ensemble (0.8·LR_fusion + 0.2·ResNet, clinical 포함)
$ python scripts/training/_legacy/run_sersnet_ensemble.py --n-repeats 5 --alpha 0.8
출력
results/runs/2026-04-XX_resnet18_v1.0.0_5fold/ artifacts/baselines/ ├── resnet18/v1.0.0/ ├── lr-fusion/v1.0.0/ └── sersnet-ensemble/v1.0.0/
💡 Legacy 는 production 에 영향 주지 않는 비교 전용 baseline. sers_predict.py 는 여전히 artifacts/usersnet/current/ 를 로드합니다.

4모델 간 성능 비교 리포트 (sers compare)

논문·대표님 보고용 head-to-head 리포트. registry 에 등록된 모델만 대상.

명령 
# uSERS-Net vs 3개 baseline
$ sers compare --models usersnet,resnet18,lr-fusion,sersnet-ensemble

# 특정 지표만 테이블로
$ sers compare --models usersnet,sersnet-ensemble --metrics auc_binary,f1

# 비교 대상 자동 선택 (registry 의 supports_compare=True 전부)
$ sers compare --models all --report results/comparisons/full_2026-04/
실제 실행 결과 예시 
$ sers compare --models usersnet --report /tmp/sers_compare_test

results/comparisons/2026-04-15_1308_usersnet_resnet18_.../ ├── report.md # 사람이 읽는 마크다운 └── metrics_table.csv # Excel/pandas 로 로드

5Production 아티팩트 빌드 + 롤백

현재 production 교체 또는 이전 버전으로 되돌리기. current symlink 가 포인터.

build 명령 
# uSERS-Net (stacking) production 빌드 — 전체 데이터 사용
$ sers production --stacking

# PDS calibration 도 같이 fit
$ sers production --stacking --fit-pds \
    --grid artifacts/usersnet/current/common_grid.npy
버전 포인터 전환 (롤백 포함) 
$ cd artifacts/usersnet/

# 현재 포인터 확인
$ ls -la current
current -> v1.0.0

# v1.0.1 로 전환
$ ln -sfn v1.0.1 current

# 롤백 (v1.0.0 로 복귀)
$ ln -sfn v1.0.0 current

# 사용 가능한 버전 목록
$ ls -d v*
v1.0.0  v1.0.1
배포 영향 확인 
$ python -c "
from pathlib import Path
p = Path('artifacts/usersnet/current').resolve()
print('Current production:', p.name)
"
🚨 sers_predict.py · webapp 이 실행 중이면 재시작해야 새 버전이 메모리에 로드됩니다. 또한 롤백 전에 예측 캐시를 flush할 것.

새 실험 / 새 모델

6새 실험 스크립트 만들기

아이디어 → 실제 실험 → 결과 저장까지 5단계.

#판정 질문배치
1이게 일회성 실험이다? (재사용 안 함)scripts/experiments/
2사후 분석이다? (confounding, SHAP 등)scripts/analysis/
3논문/포스터 figure 생성?scripts/figures/
4여러 스크립트가 같은 helper 씀?helper 는 src/sers/ 로
5결과는 어디로 가나?results/{카테고리}/{exp_name}_{YYYY-MM-DD}/
템플릿 
# scripts/experiments/2026-04_my_new_idea.py
"""
2026-04 My New Idea
Purpose: Test whether X improves Y.
Output:  results/experiments/my_new_idea_2026-04-15/
"""
from datetime import datetime
from pathlib import Path
import json
from sers.config import load_config

PROJECT_ROOT = Path(__file__).resolve().parents[2]
RUN_ID = f"my_new_idea_{datetime.now():%Y-%m-%d}"
OUT_DIR = PROJECT_ROOT / "results" / "experiments" / RUN_ID
OUT_DIR.mkdir(parents=True, exist_ok=True)

# ...실험 로직...

(OUT_DIR / "manifest.json").write_text(json.dumps({
    "script": __file__,
    "run_id": RUN_ID,
    "timestamp": datetime.now().isoformat(),
}, indent=2))
💡 manifest.json 을 매 실행마다 저장하면 6개월 뒤에도 "이 결과는 어떤 명령으로 나왔지?" 를 한눈에 복기할 수 있습니다.

7새 모델 registry 에 등록하기

새 아키텍처를 만들면 sers compare, sers train --model 에 자동으로 나타나게.

5단계

1. 모델 정의 모듈 생성:

src/sers/models/experimental/my_model/ ├── __init__.py ├── model.py # 아키텍처 └── README.md # 가설 + 상태

2. src/sers/models/_registry.py 에 ModelSpec 추가:

"my-model": ModelSpec(
    key="my-model",
    display_name="MyModel",
    category="experimental",            # or "baseline-legacy" / "production"
    module="sers.models.experimental.my_model",
    train_script="scripts/training/train_my_model.py",
    eval_script=None,
    artifact_dir="artifacts/experimental/my-model/v1.0.0",
    paper_name="MyModel (experimental)",
    supports_clinical=False,
    supports_compare=False,
),

3. docs/MODEL_STATUS.md 에 같은 키 + 사유 기재 (parity 테스트가 강제):

### 🧪 Experimental — My Model

| 파일 | 역할 | 이동 목적지 |
|---|---|---|
| src/sers/models/experimental/my_model/ | 새 아키텍처 | 동일 |

4. 학습 스크립트 생성 scripts/training/train_my_model.py

5. 테스트:

$ pytest tests/test_model_registry.py -q
======================== 7 passed ========================

$ sers compare --models my-model
Wrote results/comparisons/.../report.md
⚠️ Step 3 (MODEL_STATUS.md) 를 빠뜨리면 test_registry_parity_with_status_doc 테스트가 실패합니다. 이는 의도된 강제입니다 — 코드와 문서가 어긋나지 않도록.
